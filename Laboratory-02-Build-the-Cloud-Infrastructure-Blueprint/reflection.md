# Mission Reflection

Completing this laboratory activity gave me a clearer understanding of how cloud infrastructure works in a practical environment. By using the KillerCoda Playground, I was able to explore a Linux server and see actual system resources instead of only reading about them. I learned how compute, storage, networking, and the operating system work together to support a cloud environment.

Among the infrastructure components, I consider **compute resources** to be very important because they allow the server to perform operations and handle workloads. The CPU, CPU cores, and RAM provide the resources needed for commands and applications to run. If the server does not have enough computing resources, its performance can be affected.

The activity also showed me how Linux can support cloud computing. Linux provides a reliable environment where system resources can be examined and managed through terminal commands. I used commands such as `cat /etc/os-release`, `uname -r`, `lscpu`, `nproc`, `free -h`, `df -h`, `findmnt`, `hostname`, and `hostname -I` to gather information about the server. Learning the purpose of these commands helped me become more comfortable working with a Linux terminal.

Another important lesson was the value of technical documentation. Recording system information makes the infrastructure easier to understand, maintain, and review. Proper documentation can also be useful when checking configurations or investigating issues later.

During this laboratory, I developed skills in Linux command-line operations, system resource identification, Markdown formatting, and GitHub documentation. I also improved my ability to organize technical information in a clear way.

My GitHub portfolio became more complete after adding the laboratory documentation, cloud provider comparison, infrastructure information, diagram, and reflection. Overall, the activity improved my practical knowledge of Linux and gave me a better foundation for understanding cloud infrastructure.
